# Philippine Personal Data Breach Response

Use current NPC breach rules and submission guidance at incident time.

## Runbook

1. Open incident record and preserve evidence.
2. Contain the incident without destroying forensic information.
3. Determine affected systems, records, data types, subjects and exposure window.
4. Distinguish security incident from personal data breach.
5. Assess likely risk/harm under current DPA/NPC criteria.
6. Consult DPO/privacy/legal and incident leadership.
7. Determine whether NPC and affected data subjects must be notified and the current deadline/channel/content.
8. Submit through the current official NPC mechanism when required.
9. Keep decision evidence even when notification is not required.
10. Remediate root cause, monitor recurrence and update controls/PIA.

## Engineering support

Systems should make breach assessment possible through:

- asset/data ownership;
- tamper-resistant time-synchronized logs;
- authentication and authorization audit trails;
- deployment/change history;
- data export/download history where proportionate;
- backup/restore records;
- vendor/subprocessor escalation paths;
- ability to identify affected tenants/data subjects without excessive manual reconstruction.

Do not encode a permanent notification deadline from memory. Verify the current controlling rule when an incident occurs.
