# Product Design Review

## Flow
- Can a new user identify the primary action?
- Does the flow match the user's mental model?
- Are unnecessary steps removed?
- Can users recover from mistakes?

## Information architecture
- Labels use domain language consistently.
- Navigation reflects user jobs, not internal implementation.
- Related information/actions are grouped.

## Interaction
- Feedback is immediate and specific.
- Async actions communicate progress.
- Disabled states explain prerequisites when useful.
- Confirmation is reserved for consequential actions.

## Visual
- One clear hierarchy rather than many competing cards.
- Typography sizes/weights are purposeful.
- Spacing follows a system.
- Icons supplement meaning rather than replace ambiguous labels.

## Accessibility
- Logical heading order.
- Form associations and error announcements.
- Focus management for overlays.
- Touch targets usable on mobile.
