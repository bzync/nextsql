# NextSQL 0.0.7 — performance, CLI ergonomics, driver parity, and repository infrastructure

This release introduces B+Tree index scan optimizations for aggregate extrema, scalar function arity enforcement, active session termination (`KILL SESSION`), CLI standard input piping and CSV export, client-side statement caching across all official drivers, Studio workspace enhancements, and a modernized repository and developer toolchain setup.

## SQL engine and query optimization

- `SELECT MIN(col)` and `SELECT MAX(col)` on indexed columns now perform an instantaneous single-row index seek / backward seek, avoiding full table and secondary index scans.
- Strict arity enforcement across all built-in scalar and aggregate functions. Missing or excess arguments fail fast during binding with `invalid_argument`.
- Added administrative `KILL SESSION '<session_id>'` statement. Terminates the client's TCP connection, aborts active transactions, frees held locks, and unregisters the session immediately.

## CLI and operational ergonomics

- Added standard input piping support to `nextsql exec` (`cat script.sql | nextsql exec` or `nextsql exec - < script.sql`) with a bounded 64 MiB input guard.
- Added `--csv` flag for RFC 4180 compliant CSV output formatting with quote escaping.
- Added `--time` / `-t` execution timer flag reporting elapsed wall time to stderr without polluting stdout pipelines.
- Added `--table` / `-t` ASCII border table formatting and `--expanded` / `-x` vertical record view for terminal readability.

## Driver parity and client caching

- Extended Python (`nextsql.Connection`, `nextsql.Pool`), PHP (`NextSQL\Client`, `NextSQL\Pool`), and Ruby (`NextSQL::Connection`, `NextSQL::Pool`) drivers with client-side prepared statement LRU caching (`statement_cache_size=50` default). Evicted handles automatically close on the server (`Protocol::TYPE_CLOSE_STMT`).
- Extended the Go driver's `database/sql` DSN parser to support `read_consistency` (`strong`, `bounded`, `stale`), `max_staleness`, `realm`, and cluster node addresses.

## NextSQL Admin and Studio

- Query tabs support inline double-click renaming and tab duplication, persisted across sessions in browser localStorage drafts.
- Added 1-click EXPLAIN query plan JSON export for inspection and archiving.
- Retested automated headless Chrome axe accessibility test suite with 0 WCAG 2.2 AA violations across Setup, Operations, and Studio modes.

## Repository and Git infrastructure

- Standardized Git configuration with universal LF line ending normalization and binary file safety protections (`.gitattributes`).
- Added universal multi-language editor configuration (`.editorconfig`).
- Upgraded root `Makefile` with self-documenting ANSI help (`make help`), binary build targets (`make build`), polyglot driver testing (`make test-drivers`), formatting (`make fmt`), and local toolchain audit (`scripts/dev-doctor.sh` / `make doctor`).
- Added fast GitHub Actions quality workflow (`.github/workflows/quality.yml`) and community governance templates (`CODEOWNERS`, `PULL_REQUEST_TEMPLATE.md`, and issue forms).

## Upgrade and compatibility

Stop the daemon, install the 0.0.7 Linux packages, and restart it. Confirm both the CLI and daemon report `0.0.7`.
There are no storage, WAL, catalog, or network protocol format breaks relative to 0.0.6. All retained release fixtures from previous versions replay cleanly.

Container users pin `docker.io/bzynchub/nextsql:0.0.7`. Image tags and release assets are immutable.
